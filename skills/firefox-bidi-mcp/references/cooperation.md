# 用户实例保护（用户在 Firefox 里开着本实例时）

> 从 SKILL.md §1.4 拆出。操作页面之前先判断是否触发本条。

## 用户在 Firefox 里开着本实例：另开同档案窗口，别动他的标签页

**触发判据**（可检验）：`browser_list_tabs` 的结果里，**存在 URL 指向本 DSH 实例 Web GUI 的标签页**
（形如 `http://127.0.0.1:<本实例端口>/`，端口取自会话上下文给的 GUI 地址，或 `netstat` 里 dsh 的
LISTENING 端口）⇒ 视为「**用户可能正在通过 Firefox 使用本实例**」。

- 标签页在、但窗口最小化或在后台，**一样算** —— 无法可靠知道用户什么时候回来看，按最保守的处理。
- 用的是别的浏览器（Chrome/Edge/系统默认浏览器）打开 GUI ⇒ **不触发**本条。

**处置**：凡是要**操作页面**的动作 —— 导航、点击、输入、运行 JS、滚动、关闭/移动标签、改设置 ——
**先 `browser_new_window { url: <目标页> }` 把要操作的页面以「同档案新窗口」打开**，
之后所有动作都带这个**新窗口的 context id**；

⛔ **不要在用户的窗口里** `browser_navigate` / 点击 / 输入 / 关闭标签 —— 那会把用户正在看的内容换掉。

| 概念 | 含义 |
|---|---|
| **同档案** | Firefox 单个实例内的新窗口**天然共享同一 profile**（cookie / 登录态 / 书签 / 历史都在）⇒ 直接 `browser_new_window` 即可 |
| ⛔ **不要**用 `launch-firefox.mjs`「为了隔离」 | 它带 `-no-remote --new-instance` 起的是**另一个实例/另一个档案**，登录态全空，还可能占满 BiDi 会话 |

- **只读动作不触发**：`browser_list_*` / `browser_get_*` / `browser_screenshot` 直接读用户窗口即可。
- **例外**：用户明确说「就在当前标签做」「用我这个标签」时，按用户说的做。
- **收工**：自己开的新窗口，操作完**默认关掉**（§五 清理纪律）；若结果需要用户看（登录成功页 / 待确认的表单），
  **保留**并在答复里说明「我开了一个新窗口，标签是 X」。
- 新窗口可能被系统带到前台（抢焦点）。需要时用 `browser_activate_tab` 把用户的**原标签**切回前台。

**为什么**：本实例 GUI 的标签页是**用户的工作现场**；在上面导航/切页/关闭，等于把用户正在看的东西换掉，
代价远大于「另开一个窗口」。本条的优先级高于「少开窗口」的洁癖。
